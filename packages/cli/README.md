# @cosplaying/cli

Private workspace package. The root package exports it as `cosplaying` and `cosplaying/cli`. `packages/cli/bin/cosplaying.js` calls `main` from `src/main.js`.

## What it does

Parses the CLI and runs `hook`, `agent-hook`, `rewrite`, `install`, `uninstall`, `doctor`, and `plugin`, plus `--help` and `--version`. It rewrites shell text, answers harness hook events, and installs, removes, and checks harness hooks.

## Scope

In scope: argv for those commands, shell rewrite through `unbash`, harness-label model flags, Claude session model files under the user config directory, hook-order repair, and the doctor report. Harness paths, events, hook responses, and the Pi and OpenCode extension source live in `@cosplaying/adapters`.

Quoted strings, `bash -c` and `eval` arguments, and script files named with `source`, `.`, or `bash` stay as written. Command substitutions are rewritten. `env`, `command`, `builtin`, `exec`, `sudo`, `nohup`, `time`, and `xargs` are skipped as wrappers. An `rtk` prefix inserts `proxy` before the replacement unless `proxy` is already the next word.

`hook` calls the plugin `run` function. When `COSPLAYING_INSIDE_HOOK` is `1`, it spawns the real binary and skips `run`. A pre-tool event can write allow or deny JSON. Harness trust settings are outside this package. Pi and OpenCode extension files are generated by `@cosplaying/adapters` and do not import this package. `git` and `gh` ship in `plugins/` and stay off until enabled. `cosplaying install` does not enable them.

## Public API

Exported from `src/index.js`:

- `main(argv, options)` parses argv with commander and returns an exit code. `options` may set `stdout`, `stderr`, `env`, `cwd`, `home`, `platform`, `spawnImpl`, `stdin`, and `input`. No argv writes help and returns `2`. `--help` and `-h` return `0`. `--version` and `-v` return `0`. Usage and model-flag errors return `2`. A missing plugin, a missing binary, a failed plugin install, uninstall, enable, or disable, and a thrown error return `1`. `hook` returns the plugin `run` value, or `0` when that value is missing. When `COSPLAYING_INSIDE_HOOK` is `1`, `hook` returns the spawn status, or `1` when that status is missing. `plugin enable <name>` and `plugin disable <name>` edit `config.json` in the user config directory for the shipped plugins `git` and `gh`. A YAML user settings file is left unchanged. Pi and OpenCode extensions are regenerated after enable and disable.
- `renderHelp(plugins)` returns the help text: the core commands, then a `Plugins:` section when `plugins` is non-empty.
- `unknownHarness(id)` returns the unknown-harness error text. That text names `claude-code`, `codex`, `cursor`, `gemini`, `opencode`, and `pi`.
- `rewriteShellCommand(input, routes)` returns `{ command, changed }`. `routes` maps a command token to the text that replaces that executable word. The raw word is matched before its basename. A parse failure returns the original text with `changed: false`.
- `rewriteModelFlags(input, model)` returns `input` when `model` is empty or one of `Claude Code`, `Codex`, `Cursor`, `Gemini CLI`, `OpenCode`, or `Pi`. Otherwise, on a `hook` invocation of this CLI, a harness-label `--model` or `--model-base64` becomes `--model-base64` of `model`. A value outside those labels stays as written.
- `installHarness(harness, options)` and `uninstallHarness(harness, options)` write or remove one harness file and return its path. An unknown id throws. `installAll(options, harnesses)` and `uninstallAll(options, harnesses)` do that for each id and return `{ harness, file, ok, changed }` for each one. A failure sets `ok` to false and the next id still runs. The default list is `claude-code`, `codex`, `cursor`, `gemini`, `opencode`, and `pi`.
- `repairHookOrder(options)` returns `{ repaired, conflicts, failures }`. A later pre-tool command matching `rtk hook` is repaired by reinstalling that JSON harness. A lookalike command without the owner marker, and a file that cannot be read, are returned and left unchanged.
- `runAgentHook(harness, eventName, context)` reads one JSON object from `context.input` when that is set, otherwise from stdin, and writes the harness response.
- `runDoctor(options)` returns `0` when it records no findings and `1` when it does. It always runs `repairHookOrder`. `options.repair` also regenerates a drifted Pi or OpenCode extension and rewrites a hook whose `node` executable is missing. Each user harness file is required. When `projectDir` is set, each project file is required too. Otherwise a missing project file at a git root is not a finding. An existing project file without the owned hook is a finding, and a Pi or OpenCode file that differs from the current extension is a finding unless `options.repair` rewrites it. A missing harness binary is printed and is not a finding. `main` returns `2` for invalid doctor arguments.

## Related packages

`@cosplaying/adapters` owns each harness. `@cosplaying/hooks` edits the hook files. `cosmiconfig` loads settings and `zod` checks their shape. `@cosplaying/plugin` loads plugins and resolves the real binary. `@cosplaying/attribution` renders the bylines passed into a plugin. Failures throw `CosplayError` from `@cosplaying/errors`.
